# 속성 영향도 판정 기준

속성을 많이 늘리면 정의는 풍부해지지만, 추천에 영향이 없거나 오히려 해가 되는 속성도 섞인다.
그래서 속성마다 **추천 로직에서 하는 일**을 재고, 기준에 따라 유지·보류·제거를 정한다.

## 속성이 추천에 영향을 주는 길 두 가지

| 길 | 어디서 | 재는 방법 |
|---|---|---|
| 점수 | 대체재 유사도 (`score`) | 그 속성의 가중치를 0으로 두고 다시 평가 → 성능 변화(Δ종합) · 상위 5 추천 변동률 |
| 구조 | 정책(아이덴티티·규격·보완·제한·앵커) · TPO 추론 · 콤보 장면 · 콤보 예산 | 정책·TPO 파일에서 그 속성을 쓰는지 |

구조로 쓰이는 속성은 점수 영향이 없어도 뺄 수 없다. 예: 알코올은 유사도에는 영향이 거의 없지만 맥주 ↔ 소주 대체를 막는 규격 정책이 쓴다.

## 판정 규칙 (`python cvs.py impact` → `out/attribute_impact.csv`)

**1단계 — 점수 역할** (`ontology/policy.yaml attribute_impact`)

| 점수 역할 | 조건 |
|---|---|
| 미사용 | 현재 뎁스 밖이거나 가중치 0 (점수에 안 들어감) |
| 기여 | 빼면 종합 점수가 0.005 이상 떨어짐 |
| 노이즈 | 빼면 종합 점수가 0.005 이상 오름 |
| 보류 | 종합 점수 변화는 없는데 상위 5 추천이 10% 이상 바뀜 — 정답셋이 못 재는 영향이므로 검수로 판단 |
| 미미 | 그 외 |
| 보관 | 이 판정으로 가중치를 0으로 둔 속성 (정의·데이터는 남김) |

종합 점수 = (AUC + MRR) / 2, 정책까지 적용한 최종 추천 기준, type별 정답셋으로 잰다.

**2단계 — 최종 판정**

| 구조 사용 | 점수 역할 | 판정 |
|---|---|---|
| O | 기여 | 유지 (점수·정책 둘 다 씀) |
| O | 노이즈 | 유지, **점수 가중치만 0 검토** |
| O | 미미·미사용·보류 | 유지 (정책용) |
| X | 기여 | 유지 |
| X | 보류 | 보류 → 검수 |
| X | 노이즈 | **제거 권장** |
| X | 미미·미사용 | **제거 후보** |

결측률이 30% 이상이면 판정과 별개로 "데이터 보강" 표시를 붙인다. 정보가 없어서 영향이 작게 나온 것일 수 있다.

## 적용한 결정

| 속성 | 결정 | 이유 |
|---|---|---|
| 과자 제조방식 | 가중치 1.5 → 0 | 노이즈. 대체는 튀김·구움보다 맛·식감이 가른다 |
| 라면 국물베이스 | 가중치 1.5 → 0 | 노이즈. 손님은 소고기·된장·해물 베이스를 구분하지 않고 얼큰 국물이면 대체한다(신라면 ↔ 안성탕면 ↔ 너구리 O). 정답셋에서 베이스가 다른 O 쌍이 15개였다 |
| 유탕여부 · 면 · 카페인 | 가중치 → 0 | 영향 미미, 다른 속성과 정보 중복 |
| 제조사 · 용기 | 그대로 | 뎁스 밖이라 이미 점수에 안 쓰임. 비용이 없어서 둔다 |

정리 후 종합 점수: 과자 0.842 → 0.866, 라면 0.907 → 0.944. 정의와 데이터는 남겨서 나중에 다시 켤 수 있다.

## 지우지 않고 가중치 0으로 두는 이유

- 정답셋 231쌍 중 152쌍이 AI 검수 라벨이다(시드 78 · 사람 1). 사람 검수로 바뀌면 판정도 바뀔 수 있다.
- 생필품은 정답셋이 9쌍뿐이라 전부 0으로 나온다. 영향이 없다는 뜻이 아니라 잴 수 없다는 뜻이다.
- 그래서 삭제 대신 `weight: 0` 으로 두어 정의·데이터는 남기고 점수에서만 뺐다. 정답셋이 바뀌면 `impact` 를 다시 돌려 되살릴 수 있다.
