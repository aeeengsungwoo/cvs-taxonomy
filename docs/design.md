# 우리동네GS 추천 온톨로지 설계

대체재 · 보완재 · 트렌드 · 콤보 추천 / 범위: 과자 43 · 라면 18 · 음료 27 · 생필품 17 (시드)

## 1. 목표

우리동네GS 상품 추천을 온톨로지 그래프DB로 만든다. 추천은 네 가지다.

| 추천 | 질문 | 그래프 표현 |
|---|---|---|
| 대체재 | 이게 없으면 뭘 사면 되나 | `(:Product)-[:SUBSTITUTE {strength}]->(:Product)` |
| 보완재 | 이거랑 같이 뭘 사면 좋나 | `(:Product)-[:COMPLEMENT {strength, reason}]->(:Product)` |
| 콤보 | 이 상황(TPO)에 뭘 묶어 사나 | `(:Combo)-[:FOR]->(:Scene)-[:AT]->(:TPO)`, `(:Combo)-[:INCLUDES {role}]->(:Product)` |
| 트렌드 | 요즘 뭐가 뜨나 | `(:Product)-[:IN_TREND {score}]->(:Trend {period})` |

핵심은 **튀는 추천 방지**다. 유사도 점수만으로는 짜파게티의 대체재로 비빔면이, 일반 콜라의 대체재로 제로 콜라가, AA 건전지의 대체재로 AAA가 나온다.
그래서 TPO와 상품간·규격·속성·아이덴티티 정책을 온톨로지로 정의하고, 정책을 통과한 것만 추천 간선으로 만든다.

## 2. 진행 순서

과자 → 라면 → 생필품 → 음료 순서로 같은 루프를 반복했다. 카테고리가 바뀌어도 절차는 같고 축과 정책만 바뀐다.

1. 카테고리 트리를 정의와 함께 추가
2. 공통 축 재사용 여부 결정, 고유 축 정의
3. 아이덴티티 · 대체재 · 규격 정책
4. 속성 → TPO 추론 규칙
5. 카테고리를 넘는 보완재 규칙
6. 시드 상품 + 정답셋 → sweep → 검수 → 그래프 적재

## 3. 속성 증강 파이프라인

```
원본 상품 (이름·카테고리·속성 표기)
  ① 정규화      동의어 흡수(청양→매운맛, 제로→당 없음), 처음 보는 값은 비우고 후보 큐로
  ② 속성 부여    뎁스1 정체성 → 뎁스2 감각 → 뎁스3 상황·가치 → 뎁스4 세부
  ③ TPO 추론    속성 → 시간·장소·날씨 (규칙 기반, 상품마다 손으로 찍지 않음)
  ④ 아이덴티티   과자·음료 카테고리 2단계 / 라면 조리형태 / 생필품 카테고리 3단계
  ⑤ 점수        type별 뎁스 가중 유사도 (sweep으로 뎁스·가중치 결정)
  ⑥ 정책 필터    상품간·규격·속성·아이덴티티·제한 상품·TPO 하드 조건
  ⑦ 간선 강도    검수 결과 반영 (O=바닥 0.5, X=삭제, 미검수=20% 할인)
  ⑧ 콤보        장면(TPO)별 슬롯 채우기, 정체성 중복·예산 초과·제한 위반 제외
  ⑨ 그래프 적재  Neo4j (out/graph.cypher)
  ⑩ 인간 검수    out/audit.md · review/queue.csv → ⑤로 돌아감
```

## 5. 속성과 뎁스

속성 27개(점수용 25 + 앵커 정책 전용 `line`·`menu`), 값마다 정의와 동의어가 있다(`taxonomy/schema.yaml`).

| 뎁스 | 의미 | 공통 | 과자 | 라면 | 음료 | 생필품 |
|---|---|---|---|---|---|---|
| 1 정체성 | 무엇인가 | 카테고리 | 주원료·유탕·제조방식 | 유탕·포장형태·조리형태 | 주원료·알코올·탄산 | 용도·규격 |
| 2 감각 | 어떤 맛인가 | 맛계열 | 맵기·식감·형태 | 맵기·국물베이스·면 | 카페인·당 | — |
| 3 상황·가치 | 언제·얼마에 | 가격대·용량·구매상황 | | | 음용온도·용기 | |
| 4 세부 | 누가 | 주타깃·제조사 | | | | |

뎁스는 type별로 추천 가중치를 돌려서 정한다. 뎁스 1~4마다 뎁스별 가중치 배수(0.25/0.5/1/2)를 전부 돌리고,
정책까지 적용한 최종 추천을 정답셋 기준 AUC(대체 O가 X보다 높게 나오는 비율)와 MRR(대체 O 후보의 순위)로 잰다.

| type | 정답셋 | 선택 뎁스 | AUC | MRR |
|---|---|---|---|---|
| 과자 | 139 | ≤3 | 0.849 | 0.883 |
| 라면 | 58 | ≤2 | 0.955 | 0.933 |
| 음료 | 25 | ≤2 | 1.000 | 1.000 |
| 생필품 | 9 | ≤1 | 0.833 | 0.706 |

시드 정답셋(9~33쌍)일 때는 과자가 제조사 배수 2(뎁스4)로 과적합됐다. 검수 루프로 정답셋을 231쌍으로 늘리자
과자 ≤3, 라면·음료 ≤2로 정리됐고 제조사는 점수에서 빠졌다. MRR은 동점을 절반만 앞선 것으로 센다(동점 1.0 과대평가 방지).

### 5-1. 속성 영향도

늘린 속성이 실제로 추천에 쓰이는지 `python cvs.py impact` 로 잰다. 속성 하나를 빼고(가중치 0) 다시 평가해서
점수 역할(기여 · 노이즈 · 보류 · 미미 · 미사용)을 정하고, 정책·TPO가 쓰는 속성은 점수 역할과 무관하게 유지한다.

| 판정 | 속성 |
|---|---|
| 보관(가중치 0) — 노이즈 | 과자 제조방식(빼면 +0.010), 라면 국물베이스(빼면 +0.027) |
| 보관(가중치 0) — 미미 | 과자·라면 유탕여부, 라면 면, 음료 카페인 |
| 그대로 둠 | 제조사, 음료 용기 (뎁스 밖이라 이미 점수에 안 씀) |

정리 후 종합 점수: 과자 0.842 → 0.866, 라면 0.907 → 0.944.

기준과 해석은 [`attribute_impact.md`](attribute_impact.md).

## 6. 카테고리별 대응방침

| 관점 | 과자 | 라면 | 음료 | 생필품 |
|---|---|---|---|---|
| 목적 | 간식·디저트·안주 | 식사대용 | 갈증해소·각성·식사곁들임·음주 | 긴급·외박·비축 |
| 정체성 | 카테고리 2단계 | 조리형태 | 카테고리 2단계 | 카테고리 3단계 |
| 대체 조건 | 대분류 + 구매상황 겹침 | 조리형태 + 구매상황 겹침 | 카테고리 2단계 + 구매상황 겹침 | 품목 + 규격 일치 |
| 특유의 정책 | 맵기 1단계 | 봉지 → 사무실 제외, 봉지 ↔ 컵 대체 금지 | 제로(당 2단계), 알코올 0단계, 주류 제한 | 규격 일치(AA≠AAA), 감각 축 없음 |

생필품은 먹는 것이 아니어서 감각 축(맛·식감·맵기)을 아예 적용하지 않는다. 규격이 없는 품목은 빈 칸을 '해당 없음'으로 본다.
TPO가 하나도 추론되지 않는 생필품(건전지 등)은 중립이라 어떤 장면에서도 막히지 않는다. 우산처럼 카테고리를 넘는 연결은 보완재가 아니라 콤보 장면(비 오는 날 퇴근길)으로 만든다.

## 7. 정책 (튀는 추천 방지)

`ontology/policy.yaml`. 정책은 하드 조건이다. 점수가 아무리 높아도 어기면 간선을 만들지 않는다.

| 정책 | 정의 |
|---|---|
| 아이덴티티 | 손님이 '같은 종류'라고 느끼는 단위. 같은 정체성끼리만 대체, 다른 정체성끼리만 보완 |
| 상품간 — 대체재 | 같은 욕구를 채우는가. 같은 type, 구매상황 겹침 |
| 규격 | 가격대·용량 1단계, 맵기 1단계, 당 2단계, 알코올 0단계 이내, 생필품 규격 일치 |
| 상품간 — 보완재 | 같이 사면 가치가 커지는가. 다른 정체성, 시간대 겹침 |
| 제한 상품 | 주류는 어린이 대상 상품과 보완·콤보로 묶지 않음 |
| 콤보 | 장면 TPO 적합 + 정체성 중복 없음 + 제한 정책 + 예산 이내 |
| 트렌드 | 점수 0.3 이상 + 위 정책 통과 |

정책이 막은 예 (시드 기준 81건 중):

| 추천 후보 | 유사도 | 막은 정책 |
|---|---|---|
| TOP 스위트아메리카노 → TOP 더블랙 | 0.875 | 규격: 당 많음 → 없음 |
| 코카콜라 → 코카콜라 제로 | 0.812 | 규격: 당 많음 → 없음 |
| 듀라셀 AA → 듀라셀 AAA | 0.75 | 아이덴티티: 규격 다름 |
| 좋은느낌 중형 → 바디피트 대형 | 0.75 | 아이덴티티: 규격 다름 |
| 하리보 → 자일리톨 껌 | 0.578 | 상품간: 구매상황 겹침 없음 |
| 짜파게티 → 팔도비빔면 | 0.6 | 아이덴티티: 조리형태 다름 |

검수에서 O를 받았는데 정책에 걸리면 '정책 충돌'로 따로 보고한다. 현재 1건(2080 칫솔 ↔ 여행용 칫솔세트)이며, 정책과 검수 중 어느 쪽이 맞는지 사람이 정한다.

## 7-1. 대체 기준(앵커)

속성 유사도만으로는 손님이 무엇을 놓지 않으려는지 모른다. 불닭볶음면을 찾는 손님에게는 같은 라인(까르보불닭)이 맞고,
오모리 김치찌개라면은 브랜드(오모리)와 메뉴(김치) 중 무엇이 기준인지 데이터로 정할 수 없다.

| 조건 | 앵커 |
|---|---|
| 라인·메뉴가 둘 다 있음 | 사람이 정함 (`review/anchor.csv`) |
| 같은 라인 후보가 있음 | line |
| 같은 메뉴 후보가 있음 | menu |
| 그 외 | category |

앵커가 같은 후보는 유사도 +0.25, 상위 k 밖이어도 후보에 들어간다. 하드 정책은 뚫지 못한다.
자세한 내용은 [`anchor_policy.md`](anchor_policy.md).

## 8. TPO

`ontology/tpo.yaml`. 상품마다 TPO를 찍지 않고 속성에서 추론한다.

| 차원 | 값 |
|---|---|
| 시간대 | 아침, 점심, 오후, 저녁, 심야 |
| 장소 | 집, 사무실·학교, 야외·캠핑, 이동중 |
| 날씨 | 더움, 추움, 비 |
| 구매상황 | 간식, 술안주, 식사대용, 야식, 디저트, 나눔, 입가심, 해장, 갈증해소, 각성, 식사곁들임, 음주, 긴급, 외박·여행, 비축 (속성) |

추론 규칙 예:

- 술안주·음주 → 저녁·심야, 집·야외
- 봉지라면 → 야외 가능, **사무실·이동중 제외**
- 국물라면·온장 캔커피 → 추움, **더움 제외** / 차가운 탄산 → 더움
- 주류 → **아침·사무실·이동중 제외** / 막걸리 → 비
- 외박·여행 → 심야·이동중 / 우천 용도 → 비

콤보 장면 7개: 심야 혼술·야식, 사무실 점심 컵라면, 오후 사무실 나눔 간식, 캠핑 저녁, 더운 날 점심, 비 오는 날 퇴근길, 갑작스런 외박.

## 9. 간선 강도

| 관계 | 강도 |
|---|---|
| 대체 — 검수 O | 0.5 + 0.5 × 유사도 (바닥 0.5) |
| 대체 — 검수 X | 간선 없음 |
| 대체 — 미검수 | 0.8 × 유사도 (상품당 상위 5, 유사도 0.55 이상) |
| 보완 — 지정 조합 | 사람이 정한 값 (짜파구리 0.9, 칫솔+치약 0.9, 면도기+폼 0.85, 불닭+우유 0.7) |
| 보완 — 속성 규칙 | 0.25~0.5 (안주+맥주 0.5, 술+숙취해소 0.5, 매운 라면+우유 0.45, 디저트+커피 0.45) |
| 콤보 궁합 | 상품쌍 보완 강도 평균, 보완 간선이 없으면 시간대 겹침 × 0.3 |

## 10. 새 상품에 없는 속성이 들어왔을 때

1. **동의어 흡수**: 기존 값의 다른 표기면 synonyms에 추가 (청양 → 매운맛)
2. **비워 두기**: 흡수가 안 되면 그 값은 점수에서 뺀다. 가장 가까운 값에 억지로 붙이지 않는다
3. **후보 큐**: `review/new_values.csv`에서 사람이 synonym / new / drop 판단. new는 정의를 함께 써야 등록된다
4. **승격 기준**: 서로 다른 상품 3개 이상에서 나오거나 추천 품질에 영향이 있을 때
5. **결측**: 해당 속성만 빼고 가중치 재정규화. 비교 가능 가중치의 70% 미만이면 그 비율만큼 감점
6. **해당 없음**: 규격처럼 일부 품목에만 있는 속성은 optional로 표시해 결측으로 치지 않는다
7. **새 축·새 카테고리**: 정의와 함께 추가. 새 축은 뎁스4로 시작해 sweep에서 기여하면 올린다

## 11. 인간 검수 루프

```
validate → sweep → review export → (사람: queue.csv에 O/X) → review import → sweep → graph → audit.md 확인
```

- 정책이 막은 쌍은 검수 큐에 올리지 않는다
- X가 많이 나오면 스키마나 정책이 그 차이를 못 잡는다는 뜻이므로 속성·정책을 고치고 루프를 다시 돈다
- `out/audit.md`: 정책 충돌, 장면별 콤보, 상품별 대체재 상위 3, 정책이 막은 추천, 처음 보는 값
