# 과자 vs 라면 — 공통점과 차이점

두 카테고리를 같은 그래프에 올리려면 **공통 속성 축**과 **카테고리별 고유 축**을 나눠야 한다.
공통 축은 카테고리를 넘는 관계(보완재, 상황 기반 추천)에, 고유 축은 같은 카테고리 안의 대체재 판단에 쓰인다.

## 공통점 (공통 속성 — `applies_to: [snack, ramen]`)

| 속성 | 뎁스 | 왜 공통인가 |
|---|---|---|
| 카테고리 | 1 | 둘 다 트리 한 곳에 속한다(과자 SNK·BIS·CAKE·CHO·CDY / 라면 RMN). |
| 유탕여부 | 1 | 스낵도 라면 면도 '튀겼냐'가 기름진 맛·건강 인식을 가른다. |
| 맛계열 | 2 | 매운맛·감칠맛·해산물처럼 같은 맛 어휘로 기술할 수 있다. 크로스 카테고리 연결의 핵심. |
| 맵기 | 2 | 같은 척도(신라면=중)로 잰다. 스윙칩·치토스(약) ↔ 라면 비교가 가능해진다. |
| 가격대·용량 | 3 | 편의점 단품 구매 단위라는 점이 같다. |
| 섭취상황 | 3 | 간식·술안주·야식은 양쪽에 다 있다. 라면+안주 스낵 같은 보완재가 여기서 나온다. |
| 주타깃·제조사 | 4 | 농심·오리온·삼양처럼 두 카테고리를 다 만드는 제조사가 많다. |

## 차이점

| 관점 | 과자 | 라면 |
|---|---|---|
| 섭취 목적 | 간식·디저트·안주 (식사 아님) | **식사대용**이 기본 |
| 조리 | 개봉 즉시 | 물·열 필요 → **포장형태(봉지/컵)** 가 조리 장소를 결정 |
| 정체성 축 | **제조방식·식감·형태**가 제품을 가른다 (튀김 vs 구움, 바삭 vs 촉촉) | **조리형태(국물/짜장/볶음/비빔)·국물베이스**가 제품을 가른다 |
| 식감 | 핵심 차별 요소 (바삭·파삭·사르르·쫀득…) | 면 굵기 정도로 단순 |
| 주원료 | 감자·옥수수·밀·카카오·당류로 다양 → 대체재 판단에 유효 | 거의 전부 밀가루 → 판별력이 없어 **속성에서 제외** |
| 대체 범위 | 같은 중분류 안에서도 맛 차이로 대체가 갈림 (포카칩 ↔ 허니버터칩) | 같은 조리형태끼리만 대체 (국물 ↔ 짜장은 대체 X, 오히려 보완: 짜파구리) |
| 나눔성 | 대용량·개별포장(초코파이) 등 '나눔' 상황이 큼 | 1인 1개가 기본 |

## 그래서 설계에 반영한 것

- 대체재(SUBSTITUTE)는 **같은 type 안에서만** 계산한다. 과자↔라면은 서로 대체하지 않는다.
- 카테고리를 넘는 관계는 **보완재(COMPLEMENT)** 로만 만든다(`config/complement_rules.yaml`).
- 라면에서 판별력 없는 주원료는 빼고, 과자에 없는 포장형태·조리형태·국물베이스·면을 넣었다.
- 생필품·음료를 추가할 때도 같은 방식으로 공통 축(가격대·용량·섭취상황·제조사)은 재사용하고 고유 축만 새로 정의한다.
