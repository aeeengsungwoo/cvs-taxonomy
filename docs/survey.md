# 페르소나 30명 품절 대체 설문

실제 품절 때 손님이 무엇을 대신 샀는지에 대한 판매 데이터가 없다. 그래서 성향이 다른 30명을 생성형 에이전트로 만들고, 상품 110개(이후 115개)가 각각 품절일 때 매대의 다른 상품 중 무엇을 대신 사겠는지 물었다.
**설문 결과가 옳다고 가정하고**, 이를 정책과 간선 강도에 반영했다.

참고한 것:
- [당근 Taxonomy 팀 — 카테고리 분류에 2조 토큰을 쓰면서 알게 된 것들](https://medium.com/daangn/2%EC%A1%B0-%ED%86%A0%ED%81%B0%EC%9D%84-%EC%B9%B4%ED%85%8C%EA%B3%A0%EB%A6%AC-%EB%B6%84%EB%A5%98%EC%97%90-%EC%93%B0%EB%A9%B4%EC%84%9C-%EC%95%8C%EA%B2%8C%EB%90%9C-%EA%B2%83%EB%93%A4-f619f1db6b7b)에서 세 가지를 가져왔다.
  - 여러 판정자의 다수결로 정답을 만들고, 그 정답을 기존 사람 라벨과 대조해 검증한다.
  - 답이 여러 개인 문제는 precision/recall로 잰다.
  - 정책을 바꿀 때는 regression 평가를 거친다.
- Amazon ESCI 라벨 체계([`esci_check.md`](esci_check.md)): 답안을 "대신 산다 / 안 산다"로 나눈 데 참고했다.

## 설계

| 항목 | 내용 |
|---|---|
| 응답자 | `survey/personas.yaml` 30명. 나이·생활 패턴, 건강 제약(당뇨·다이어트·임신·고혈압), 맵기 내성, 브랜드 충성, 가격 민감, 방문 목적을 섞었다 |
| 문항 | `tools/survey_build.py` → `survey/questions.json`. 상품 110개마다 보기 7개 |
| 보기 | 지금 추천(상위 3) + 점수 근처 상품(**정책이 막은 것 포함**) + 같은 라인. 섞어서 보여 주고, 추천인지 차단인지는 숨겼다 |
| 답 | `skip`(이 사람은 애초에 그 상품을 살 일이 없음) / `accept`(대신 살 보기, 여러 개 가능, 비면 안 사고 나감) / `best`(가장 먼저 집을 것) / `why` |
| 오염 방지 | 에이전트는 personas.yaml과 questions.txt만 읽게 했다. 기존 추천 결과(out/, review/)는 보지 못한다 |
| 판정 (`policy.yaml survey`) | skip을 뺀 응답자가 5명 이상인 보기만 판정한다. 50% 이상이 "대신 산다"면 O, 20% 이하면 X, 그 사이는 갈림 |

응답 3,300개 중 skip 674개, 응답자 1명당 평균 수용 보기 2.2개, "안 산다" 14%. 보기 527개를 판정했다: O 237 · X 170 · 갈림 120.

## 설문 검증 — 기존 라벨과 대조

| 기존 라벨 출처 | 설문과 일치 |
|---|---|
| seed (처음 만든 정답) | 45/55 (82%) |
| claude (AI 1차 검수) | 63/83 (76%) |
| admin (AI가 관리자 역할로 답함) | 9/15 (60%) |
| review (사람 검수: 불닭 → 까르보) | 1/1 |

엇갈린 곳은 대부분 맛이 정체성인 과자에서 나왔다. 기존 라벨은 같은 감자칩이면 O(포카칩 → 스윙칩 볶음고추장)였지만, 설문은 맛이 다르면 X(14%)였다. 반대로 기존 라벨이 X인데 설문이 O인 쌍은 세트 → 낱개 칫솔(97%), 순한 라면 → 사리곰탕(72%) 등이다.

## 반영 규칙

1. **상품쌍 판정**: 설문 O/X가 AI 라벨(seed·claude·admin)보다 우선한다. 사람 검수(`source=review`)만 설문보다 앞선다.
   설문 O 간선의 강도는 0.5 + 0.5 × 수용률이라서, 점원 순서 안에서 설문이 더 많이 받은 것이 먼저 나온다.
2. **정책 변경은 패턴으로만**: 같은 방향의 설문 결과가 2쌍 이상일 때만 정책을 바꾼다. 한 쌍짜리나 갈린 패턴은 정책을 그대로 두고 정책 충돌로 올린다(24건). 충돌은 아래 [정책 충돌 정리](#정책-충돌-정리)에서 한 쌍씩 결정했다.

| 정책 | 설문 근거 | 바꾼 것 |
|---|---|---|
| 라면 포장형태 | 같은 라인이면 봉지 ↔ 큰컵 4쌍 모두 O (불닭 → 불닭 큰컵 100%). 다른 라인 작은컵 → 봉지는 5쌍 모두 X | 같은 라인이면 포장형태가 달라도 허용 (`same_unless_line`) |
| 당 방향 | 같은 라인 안의 당 올림은 O (코카콜라 제로 → 코카콜라 70%, 칠성 제로 → 칠성 72%, 더블랙 → 스위트 57%). 다른 라인은 X | 같은 라인이면 허용 (`line_free`). 대신 −0.15 감점하고 점원 순서 맨 뒤로 |
| 맵기 방향 | 이미 매운 것(중 이상)을 고른 손님에게 더 매운 것은 5쌍 모두 O (까르보 → 불닭 87%) | `free_from: 중` |
| 세트 ↔ 구성품 | 세트 품절 → 칫솔·치약 낱개 97% | 양방향으로 (`two_way`) |
| 카테고리 묶음 | 물 ↔ 무가당 차 8쌍 O · 빼빼로 → 초코바 3쌍 O · 화장지·각티슈 → 물티슈 2쌍 O | `groups` 3개 (갈증 해소 음료 · 초코 간식 · 휴지류) |
| 생리대 사이즈 | 중형 ↔ 대형 ↔ 오버나이트 4쌍 O | 생리대는 규격 일치를 요구하지 않음 (`loose`) |

**바꾸지 않은 것**
- **맵기 약 → 중**: O 6 · X 8 · 갈림 6으로 갈렸다. 관리자 답 X를 그대로 둔다.
- **가격대 2단계 차이**: O 4 · X 10으로 막는 쪽이 맞다.
- **알코올 도수**: 맥주 → 소주가 4쌍 모두 X였다. 막는 쪽이 맞다.
- **카페인이 크게 오르는 쪽**: 사이다·콜라 → 에너지음료가 8쌍 모두 X였다. 막는 쪽이 맞다.

## 다수결의 함정 — 소수 보호

코카콜라 제로 → 코카콜라는 전체 70%가 받았다. 하지만 다이어트·당뇨·헬스 응답자(P01, P02, P03, P16, P19)는 **전원** 거절했다. 다수결만 따르면 제로를 고른 이유가 건강인 손님에게 일반 콜라를 권하게 된다.

그래서 이 방향은 허용하되 점원 순서 맨 뒤에 둔다. 코카콜라 제로가 품절이면 펩시 제로 → 칠성사이다 제로 → 코카콜라 순서로 권하고, 이유 문구에 "당 더 많음"을 밝힌다. 같은 당의 대안이 있는 한 일반 콜라가 먼저 나오지 않는다.

## 선별 설문 (2026-10-23)

상품이 늘 때마다 30명에게 다시 묻지 않도록 바꿨다([`limits_and_next.md`](limits_and_next.md) 대안 A).

**묻는 것** (`tools/survey_queue.py` → `survey/queue.json`)
- 설문을 한 번도 안 받은 상품(새 상품)은 보기 7개 전부를 묻는다.
- 기존 상품은 지금 1~3순위로 보여 주는데 설문 판정이 없는 보기만 묻는다.

**누구에게**: 같은 중분류 문항에서 "살 일 없음"을 고르지 않은 비율이 50% 이상인 페르소나만 묻는다. 그 비율이 높은 순으로 최대 10명, 최소 5명이다. 맥주 문항이면 술 마시는 사람에게 묻는 식이다.

**어떻게**: 에이전트 하나가 페르소나 6~7명을 차례로 답한다. 에이전트를 사람 수만큼 띄우지 않아서 고정비가 준다.
응답은 `tools/survey_merge.py` 로 기존 응답 파일에 덧붙인다. 응답마다 그때 본 보기(`shown`)와 라운드 이름을 남긴다.

**시연**: 권할 대체가 없던 팔도비빔면·듀라셀 AAA의 짝(배홍동 비빔면 · 진비빔면 · 에너자이저 AAA)을 추가했다.

| | 전수 재설문 (예전 방식) | 선별 설문 |
|---|---|---|
| 문항 | 보기가 바뀐 32문항 | 8문항 (새 상품 3 + 확인 안 된 1~3순위 5) |
| 응답 | 32 × 30명 = 960건 | 80건 (19명) |
| 토큰 | 짜장 재설문 13문항에 약 166만 (같은 방식) | **약 17만** (에이전트 3개) |

결과
- 팔도비빔면 → 배홍동 비빔면 10/10, 듀라셀 AAA ↔ 에너자이저 AAA 10/10. 권할 대체 없음이 11개에서 9개로 줄었다(상품 118개).
- 비빔면 → 짜장라면은 0/10, 불닭은 4/10(갈림)이었다. 비빔면 손님은 비빔면만 찾는다.
- 배홍동 → 진비빔면(맵기 약 → 중)은 10/10이라 정책 충돌로 잡혔고, 거절한 소수가 없어 허용했다(`review/conflicts.csv`).
- 기존 상품 1~3순위 중 확인 안 된 것: 수미칩 → 오감자 8/10 · 콘칩 → 허니버터칩 7/10은 O, 아이비 → 다이제 4/10은 갈림이라 3순위에서 빠졌다.
- 이 라운드 뒤 대기열은 0문항이다. 지금 보여 주는 1~3순위는 전부 설문으로 확인됐다.

**함께 고친 것**
- **보기별 분모**: 판정 분모를 "그 보기를 본 응답자 수"로 바꿨다. 라운드마다 보기가 달라도 섞어 셀 수 있다.
- **수용 0% 누락 버그**: 이전 집계는 누군가 고른 보기만 판정해서, 보기에 있었지만 아무도 안 고른 241쌍이 X로 잡히지 않았다. 고친 뒤 판정은 O 272 · X 431 · 갈림 128(831쌍)이다.
- **갈린 쌍 처리**(`survey.split`): 갈린 쌍은 옛 AI 라벨을 버리고 벡터 점수(미검수 할인)에 맡긴다. 세 방식을 홀드아웃으로 비교했다.

| 갈린 쌍 처리 | 선택률 | 1순위 | 헛추천 |
|---|---|---|---|
| ai (옛 AI 라벨 유지) | 0.941 | 0.890 | 0.155 |
| weak (수용률을 약한 강도로) | 0.944 | 0.886 | 0.175 |
| **none (AI 라벨 버림)** | 0.943 | 0.888 | **0.144** |

다시 묻는 방식은 쓰지 않았다. 같은 페르소나는 다시 물어도 비슷하게 답할 가능성이 높아서다.

현재(선별 라운드 포함, 짝수 페르소나 채점): 선택률 **0.946** · 1순위 **0.893** · 빈손 **0.036** · 헛추천 **0.138**.

## 3개 보여 주기 기준 평가

화면에 1~3순위를 함께 보여 주고, **손님이 그중 하나라도 "대신 사겠다"고 하면 정답**으로 본다. 응답자 한 명 한 명의 답으로 채점한다(`pick_eval`).
이 지표는 많이 보여 줄수록 오르기 때문에, 억지로 채우는지(헛추천)와 너무 소심한지(빈손)를 같이 본다.

| 지표 | 정의 |
|---|---|
| 선택률 | 대신 살 게 있는 응답 중, 보여 준 3개 안에서 하나라도 고른 비율 |
| 1순위 | 1순위를 고른 비율 |
| 빈손 | 살 게 있는데 아무것도 안 보여 준 비율 |
| 헛추천 | 보여 준 상품 중 그 응답자가 고르지 않은 비율 |

| 짝수 페르소나로 채점 (판정은 홀수) | 선택률 | 1순위 | 빈손 | 헛추천 |
|---|---|---|---|---|
| 정책만 | 0.889 | 0.824 | 0.087 | 0.187 |
| 정책 + 설문 판정 | **0.940** | **0.879** | **0.042** | **0.174** |

대신 살 게 있는 손님 100명 중 94명은 화면의 3개 안에서 고른다. 안 사고 나가는 손님(113건)에게는 89%의 경우 우리도 아무것도 권하지 않았다.

순위별로 보면 아래로 갈수록 확신이 떨어진다(과반 기준, 짝수 페르소나).

| 순위 | 권한 상품 수 | 평균 수용률 | 과반이 받은 비율 |
|---|---|---|---|
| 1순위 | 102 | 90% | 96% |
| 2순위 | 80 | 80% | 93% |
| 3순위 | 54 | 67% | 82% |

사람들이 가장 먼저 집는 상품은 우리 1순위와 76%(78/102) 같고, 3개 안에는 94%(96/102) 들어 있다.

**화면 제안**: 1~3순위를 함께 보여 주면 손님이 원하는 상품이 거의 항상(94%) 그 안에 있다. 3순위는 다섯 중 하나꼴로 과반이 안 받는 "없으면 이거라도" 대안이라 확신이 낮다. 그래서 1·2순위는 "대신 이건 어떠세요"로, 3순위는 흐리게 표시하거나 "이것도 있어요" 정도로 약하게 보여 주는 방식을 권한다.

## 정책 충돌 정리

설문은 O인데 정책이 막는 24건을 `review/conflicts.csv` 에서 한 쌍씩 결정했다(`decision` 칸).
- 허용: 그 쌍만 정책 예외로 둔다.
- 유지: 정책이 맞다고 보고 설문을 따르지 않는다.

기준은 세 가지다.

| 기준 | 결정 | 건수 | 쌍 |
|---|---|---|---|
| **소수 보호**: 건강·체질 제약 응답자(맵찔이·당뇨·임산부·노인·아이 부모)가 일관되게 거절한 방향 | 유지 | 10 | 순한 라면 → 신라면·진라면 매운맛 4 · 육개장 사발면 → 큰컵 매운 라면 2 · 튀김우동 → 매운 큰컵 3 · 흰우유 → 바나나맛우유 |
| **없으면 이거라도**: 수용은 60% 미만이고, 1순위로 고른 사람이 5% 미만 | 유지 | 6 | 포카리 → 삼다수·아이시스 · 불닭(봉지·큰컵) → 오모리김치즈 · 오모리김치즈 → 불닭 · 화장지 → 물티슈 |
| 그 외 | 허용 (설문을 따름) | 8 | 라떼 ↔ 레쓰비 · 컨디션 → 포카리 · 델몬트 → 포카리·게토레이 · 각티슈 → 물티슈 · 비빔면 → 짜파게티 · 쿠크다스 → 카스타드 |

"없으면 이거라도" 기준을 둔 이유는 이렇다. 과반이 받는다는 것과 점원이 먼저 권할 만하다는 것은 다르다. 불닭 → 오모리김치즈는 53%가 받았지만 1순위로 고른 사람은 0명이었다.
반대로 컨디션 → 포카리는 50%로 경계값이지만, 응답자 절반이 1순위로 골랐다. 숙취에 이온음료는 흔한 선택이라 허용했다.

새 충돌이 생기면 `python cvs.py graph` 가 `review/conflicts.csv` 에 decision 칸을 비워 추가한다. 이미 결정한 행은 그대로 둔다.

## 평가

`python cvs.py survey` 의 출력이다. 추천이 여러 개라 precision/recall로 잰다.
- **precision**: 권한 것 중 과반이 받은 비율
- **recall**: 과반이 받은 보기 중 권한 비율
- **top1**: 1순위가 "가장 먼저 집음" 최다 보기와 같은 비율
- **억지**: 아무도 과반으로 안 받는데 권한 문항 수
- **놓침**: 과반이 받는 게 있는데 안 권한 문항 수

과적합을 피하려고 **홀수 페르소나 15명의 판정으로 간선을 만들고, 짝수 15명의 답으로 채점**했다.

| 짝수 페르소나로 채점 | precision | recall | top1 | 억지 | 놓침 |
|---|---|---|---|---|---|
| 설문 전 정책 (main) | 0.897 | 0.577 | 0.571 | 0 | 16 |
| 설문 패턴으로 바꾼 정책만 | 0.893 | 0.617 | 0.600 | 0 | 10 |
| 바꾼 정책 + 설문 판정(홀수) | 0.915 | 0.709 | 0.695 | 0 | 6 |
| + 정책 충돌 정리 | **0.918** | **0.737** | **0.705** | 0 | 4 |

전체 30명 기준(학습과 채점이 겹침)으로는 precision 0.911 · recall 0.888 · top1 0.733, 놓침 2. 권할 대체가 없는 상품은 26개에서 11개로 줄었다.
'유지'로 결정한 16쌍은 설문 O인데도 권하지 않으므로, 설문 기준 recall을 일부러 깎는 결정이다.

정책 패턴은 30명 전체에서 뽑았으므로 홀드아웃 결과에도 약간의 누수가 있다.
가중치 재조정(`sweep`)은 하지 않았다. 생리대 관리자 답 4쌍만 늘어난 정답셋으로 다시 돌리면 생활용품 뎁스가 1에서 4로 크게 흔들렸고, 홀드아웃 recall도 0.709에서 0.694로 떨어졌다.

## 짜장라면 추가 (상품 115개)

짜파게티가 "권할 대체 없음"이었던 원인은 시드에 짜장라면이 하나뿐이어서다. 설문에서도 과반이 받은 대안이 없었다(36%는 안 사고 나감, 비빔면 32%).
GS 매대에 있는 짜장라면 5개(짜파게티 큰사발 · 사천짜파게티 · 짜왕 · 진짜장 · 짜짜로니)를 추가했다. 그리고 새 상품 문항과 보기가 바뀐 기존 문항, 합쳐서 13문항만 30명에게 다시 물었다.

| 결과 | 내용 |
|---|---|
| 짜파게티 → 다른 짜장 | 수용 77~100% (짜짜로니 100%, 진짜장 96%, 큰사발 81%) |
| 짜파게티 → 사천짜파게티 | 수용 50%, 1순위 4% — 매운 쪽은 뒤로 |
| 정책 | 같은 메뉴(짜장)면 브랜드가 달라도 봉지 ↔ 큰컵 6쌍 모두 O → `same_unless_menu: [container]` |
| 점원 순서 | 조금이라도 세지는 대안(안 매움 → 약간 매움 포함)은 같은 단계 안에서 뒤로. 홀드아웃 precision 0.918 → 0.928, top1 0.705 → 0.716 |
| 앵커 | 짜파게티 · 큰사발 · 사천은 라인 기준, 짜왕 · 진짜장 · 짜짜로니는 메뉴(짜장) 기준 |

팔도비빔면은 이번엔 "권할 대체 없음"이 됐다. 다시 물어보니 비빔면 → 짜파게티가 46%로 과반 아래로 내려갔다. 같은 방식으로 비빔면(배홍동·진비빔면 등)을 추가하면 풀린다.

## 한계

- 페르소나는 LLM이 연기한 사람이지 실제 손님이 아니다. 실제 품절 시점의 판매 데이터가 생기면 같은 형식(`survey/answers/*.json`)으로 바꿔 넣고 같은 명령으로 다시 판정한다.
- 보기에 없던 상품쌍은 측정하지 않았다. recall은 보여 준 보기 안에서의 값이다.
- 30명 구성 자체가 결과를 좌우한다. 건강 제약 응답자 비율을 바꾸면 당 방향 결과도 바뀐다.

## 실행

```
python tools/survey_build.py     # 문항 생성 → survey/questions.json, questions.txt
# 페르소나 에이전트 30개가 각자 survey/answers/P01.json … P30.json 에 답 저장
python cvs.py survey             # 판정·검증·평가 → out/survey_pairs.csv, survey_features.csv, survey_eval.csv
python cvs.py triage && python cvs.py graph && python cvs.py oos --all
```

| 파일 | 내용 |
|---|---|
| `out/survey_pairs.csv` | 보기별 응답자 수 · 수용률 · 1순위율 · 판정 · 기존 라벨 · 정책 차단 사유 |
| `out/survey_features.csv` | 차이 유형별 평균 수용률 (같은 라인 0.70 > 같은 세부 카테고리 0.63 > 다른 중분류 0.33) |
| `out/survey_eval.csv` | 상품별 추천 vs 설문 과반 (precision · recall · top1 · 억지 · 놓침) |
