# 새 상품에 '없는 속성'이 들어왔을 때 대응방침

새 과자가 들어오면 세 가지 경우가 생긴다. `python cvs.py validate` 가 전부 `review/new_values.csv` 로 뽑는다.

## 1. 값은 있는데 스키마에 없는 값 (예: 먹태깡의 맛 '마요')

처리 순서:

1. **동의어로 흡수** — 기존 값의 다른 표기면 `schema.yaml` 해당 값의 `synonyms` 에 추가한다.
   예: '청양' → `매운맛` 의 동의어 (이미 반영, 먹태깡의 '청양'은 매운맛으로 들어감).
2. **흡수가 안 되면 일단 비워 둔다** — 그 값은 점수 계산에서 빠진다. 아는 값만으로 비교하고,
   multi 속성이면 나머지 아는 값(짠맛·해산물·매운맛)은 그대로 쓴다. 모르는 값을 억지로 가장 가까운 값에 붙이지 않는다
   (잘못 붙이면 틀린 대체재 간선이 생기고, 비워 두면 간선이 약해질 뿐이다).
3. **신규 값 후보로 대기** — `new_values.csv` 의 `decision` 칸에 사람이 판단을 적는다.
   - `synonym:<기존값>` → 동의어로 추가
   - `new` → 새 값으로 승격. **정의를 반드시 같이 써서** `schema.yaml` 에 추가 (`validate` 가 정의 없는 값을 실패 처리)
   - `drop` → 의미 없는 표기, 무시
4. **승격 기준** — 같은 값이 서로 다른 상품 **3개 이상**에서 나오거나, 검수자가 추천 품질에 영향이 있다고 판단하면 승격.
   1\~2개 상품에만 있는 값은 동의어 흡수나 보류가 기본 (값이 너무 잘게 쪼개지면 유사도가 희석된다).

## 2. 값이 비어 있음 (결측, 예: 컵누들의 국물베이스)

- 해당 속성만 비교에서 빠지고, 남은 속성 가중치를 재정규화한다 → 결측이 곧 '다르다'는 감점이 되지 않는다.
- 단, 비교한 가중치가 비교 가능했던 가중치의 **70% 미만**이면 그 비율만큼 점수를 깎는다(근거 부족 할인).
  속성이 거의 빈 상품이 우연히 높은 점수로 대체재가 되는 걸 막는다.

## 3. 속성 축 자체가 없음 (예: 새 카테고리 '단백질바'의 단백질 함량)

- 카테고리가 트리에 없으면 상품을 받지 않는다(`validate` 가 unknown_value 로 잡음). 먼저 `categories.yaml` 에
  정의와 함께 노드를 추가한다. 상위 노드만 정해져도(예: CHO 아래) 트리 유사도는 바로 동작한다.
- 새 속성 축은 `schema.yaml` 에 `depth: 4` (세부)로 먼저 넣는다. 다음 `sweep` 에서 성능에 기여하면
  뎁스를 올리고, 기여가 없으면 그대로 둔다. 축을 추가할 때도 `definition` 필수.
- 기존 상품의 새 속성 값은 비어 있어도 된다(2번 결측 규칙으로 처리).

## 버전 원칙

- 스키마를 바꾸면 `sweep → graph` 를 다시 돌린다. 간선에는 `depth` 가 찍혀 어떤 설정으로 만든 간선인지 남는다.
- 사람이 검수한 쌍(`gold.csv`)은 스키마가 바뀌어도 유지된다. 검수 O 간선은 강도 0.5 바닥이 보장되고, 검수 X 쌍은 간선이 생기지 않는다.
